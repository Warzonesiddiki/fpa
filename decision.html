📌 Decision ID: D-004 · Category: Security
📅 Timestamp: 2026-09-02
📝 Title: Settings write must be HMAC-audited in the same transaction
✅ What: settings.set upserts the app-scope settings row and then appends a settings.set event to the active Company's HMAC chain in the same SQLite transaction, using the keychain-held audit key.
🧠 Why: Every mutation must be tamper-evident (AUTH-SPEC §2.5). A settings change is a write even though it is app-scoped, and chaining it means a broken chain surfaces as read-only rather than silently accepted.
❌ Rejected: Writing settings without an audit event (breaks the invariant); reusing the app-scope settings marker pattern from security.pin_setup (that marker is only pre-Company and would not chain to the active Company).
💥 Impact: src-tauri/src/commands/settings.rs::settings_set, audited_hash, next_hash. Behavior: every Save also creates one audit row for the active Company.

C. Execution Flow Map

C1. Entry Points

  • src/main.tsx → ReactDOM.createRoot → App (webview UI)
  • src-tauri/src/main.rs → tauri::Builder → lib.rs::run (desktop runtime)

C2. Call Chain — primary happy path

src/main.tsx::(root render)
  → src/App.tsx::App
    → src/router.tsx::router
      → src/pages/s001-unlock (or /welcome, /wizard)
      → src/pages/s004-shell::ShellPage (/app/*)
        → src/pages/s075-settings::SettingsPage
          → src/stores/settings.ts::syncRemote
            → src/api/bridge.ts::call("settings.get")
              → Tauri invoke | src/api/mock.ts::mockInvoke("settings.get")
          → SettingsForm::save
            → useSettingsStore::save
              → localStorage.setItem (mirror)
              → src/api/bridge.ts::call("settings.set", {key, value_json})
                → src-tauri/src/commands/settings.rs::settings_set
                  → require_session_write
                  → settings upsert (app scope)
                  → audited_hash → next_hash → INSERT audit_events
                  → tx.commit
        → src/pages/s043-drivers::DriverPage
          → src/stores/drivers.ts::upsertDriver/setValue
            → src/api/bridge.ts::call("driver.upsert" | "driver.set_value")
              → Tauri invoke | src/api/mock.ts::mockInvoke
              → src-tauri/src/commands/driver.rs::driver_upsert/driver_set_value
                  → model/scope validation → exact-decimal bounds check
                  → upsert drivers (or audited echo for set_value until S-050)
                  → audited_hash → next_hash → INSERT audit_events → tx.commit

C3. Module Dependency Graph

  • App → router → pages (settings, grid, import, …)
  • pages → stores (settings, model, import, session)
  • stores → src/api/bridge → schema (Zod) → mock | Tauri invoke
  • stores/model → src/workers/modelEngineClient → modelEngine (HyperFormula)
  • Rust: lib.rs → commands/* → core/{error,audit,money,calendar} → storage/{db,container,keys,keystore}

C4. Data Flow — Save settings / driver

Settings: Form draft → store.save → schema validate → localStorage mirror → settings.set IPC → Rust validate JSON → INSERT/UPDATE settings (app) → HMAC hash → INSERT audit_events → commit → root theme/density applied. Driver: driver.upsert validates model/name/bounds and upserts drivers; driver.set_value validates exact-decimal bounds and returns an HMAC-audited echo until the S-050 working-scenario data source exists.

C5. State & Side Effects

  • DB writes (app DB): settings, audit_events, plus Company/GL/import/model writes per their handlers.
  • File I/O: .fpa container seal/open, keychain fallback file audit.key.
  • Browser: localStorage (settings mirror, wizard draft, search history), root dataset.theme/density, AG Grid row height CSS variable.
  • In-memory: SessionState, KeyVault, ParseRegistry, ModelRegistry, HyperFormula engine.
